🧱 Esercizi — C++, programmazione a oggetti (OOP)

Dagli stessi algoritmi... agli oggetti

Con la programmazione orientata agli oggetti i dati e le operazioni che li riguardano vengono racchiusi insieme in una class, invece di restare separati come nella programmazione procedurale (vedi la pagina Esercizi C++ procedurale) — l'ultimo argomento visto lì, la struct, è proprio il ponte da cui ripartiamo.

Il percorso qui sotto è a difficoltà crescente e ricalca i quattro pilastri della OOP: incapsulamento, ereditarietà, polimorfismo e astrazione. Dal Livello 3 in poi useremo puntatori grezzi (Tipo*) con new/delete gestiti a mano, invece degli smart pointer — è più lavoro, ma è proprio la fatica di gestire la memoria manualmente a far capire, più avanti, perché gli smart pointer esistono. Prova a risolvere ogni esercizio da solo prima di rivelare la soluzione.

Come leggere le etichette degli esercizi

  • 📽️ Da proiettare — introduce un meccanismo nuovo del linguaggio o un concetto-chiave della OOP (es. this, virtual, la transizione struct→class): conviene spiegarlo e risolverlo insieme alla classe.
  • ✏️ Autonomo — riusa lo schema di un esercizio "da proiettare" già visto nello stesso blocco, con un problema diverso: adatto come esercitazione individuale, con la soluzione da rivelare solo dopo il tentativo.

1. Dagli algoritmi alle classi (riscaldamento)

Esercizio 1 — Classe Contatore 📽️ Da proiettare

Consegna: crea una classe Contatore (come quello del simulatore "assegnamento & incremento" visto nella sezione Flow Chart) che si può incrementare e leggere, poi usala in un ciclo for per contare da 0 a 4.

Mostra soluzione in C++ (OOP) 
#include <iostream>
using namespace std;

class Contatore {
    private:
        int valore;
    public:
        Contatore() : valore(0) {}
        void incrementa() {
            valore = valore + 1;
        }
        int leggiValore() {
            return valore;
        }
};

int main() {
    Contatore cont;
    for (int i = 0; i < 5; i++) {
        cout << cont.leggiValore() << endl;
        cont.incrementa();
    }
    return 0;
}

Esercizio 2 — Classe Numero (primo o no) ✏️ Autonomo

Consegna: crea una classe Numero che sappia dire da sola se è primo, poi usala per controllare tutti i numeri da 2 a 20 con un ciclo for.

Mostra soluzione in C++ (OOP) 
#include <iostream>
using namespace std;

class Numero {
    private:
        int valore;
    public:
        Numero(int v) : valore(v) {}
        bool ePrimo() {
            if (valore < 2) return false;
            for (int i = 2; i <= valore / 2; i++) {
                if (valore % i == 0) {
                    return false;
                }
            }
            return true;
        }
};

int main() {
    for (int n = 2; n <= 20; n++) {
        Numero num(n);
        if (num.ePrimo()) {
            cout << n << " e' primo" << endl;
        }
    }
    return 0;
}

Esercizio 3 — Classe Lettore (do-while) ✏️ Autonomo

Consegna: crea una classe Lettore con un metodo leggiPositivo() che continui a chiedere un numero finché non ne riceve uno positivo, e lo restituisca.

Mostra soluzione in C++ (OOP) 
#include <iostream>
using namespace std;

class Lettore {
    public:
        int leggiPositivo() {
            int n;
            do {
                cin >> n;
            } while (n <= 0);
            return n;
        }
};

int main() {
    Lettore lettore;
    int n = lettore.leggiPositivo();
    cout << "Hai inserito: " << n;
    return 0;
}

Anche dentro un metodo di una classe, il ciclo do-while funziona esattamente come nella programmazione procedurale: esegue il corpo almeno una volta.

Esercizio 4 — Dalla struct alla class: Libro ⭐ 📽️ Da proiettare

Consegna: parti da una struct LibroStruct (solo dati: titolo, autore, anno) usata insieme a una funzione esterna stampaScheda(), come nella sezione di teoria "Dalla struct alla class". Trasformala in una class Libro che incapsuli lo stesso comportamento come metodo, aggiungendo anche eClassico() (vero se l'anno è precedente al 1990).

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

// Prima versione: una struct (solo dati) e una funzione ESTERNA che la usa
struct LibroStruct {
    string titolo;
    string autore;
    int anno;
};

void stampaScheda(LibroStruct l) {
    cout << l.titolo << " di " << l.autore << " (" << l.anno << ")" << endl;
}

// Seconda versione: una class che incapsula dati E comportamento insieme
class Libro {
    public:
        string titolo;
        string autore;
        int anno;

        void stampaScheda() { // stesso identico calcolo di prima, ma ora e' un METODO della classe
            cout << titolo << " di " << autore << " (" << anno << ")" << endl;
        }

        bool eClassico() {
            return anno < 1990;
        }
};

int main() {
    LibroStruct l1 = {"Il nome della rosa", "Umberto Eco", 1980};
    stampaScheda(l1); // con la struct, il "comportamento" resta fuori, come funzione a parte

    Libro l2;
    l2.titolo = "Il nome della rosa";
    l2.autore = "Umberto Eco";
    l2.anno = 1980;
    l2.stampaScheda();                                              // il comportamento e' "dentro" l'oggetto
    cout << (l2.eClassico() ? "E' un classico" : "Non e' un classico") << endl;

    return 0;
}

Il dato (titolo, autore, anno) non è cambiato: quello che cambia è dove vive il comportamento. Con la struct, stampaScheda è una funzione a parte che deve ricevere il libro come parametro; con la class, lo stesso comportamento diventa un metodo richiamabile direttamente sull'oggetto (l2.stampaScheda()). Questo è il cuore dell'incapsulamento: dati e azioni che li riguardano racchiusi in un'unica entità.

Esercizio 5 — Da funzione a classe: Automobile ⭐ ✏️ Autonomo

Consegna: trasforma una funzione libera che calcola il bollo di un'automobile in una vera classe Automobile con attributi targa, prezzo e porte, un costruttore e un metodo calcolaBollo(). Crea due oggetti con dati diversi e stampa il bollo di entrambi.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class Automobile {
    public:
        string targa;
        double prezzo;
        int porte;

        Automobile(string t, double p, int np) : targa(t), prezzo(p), porte(np) {}

        double calcolaBollo() {
            return prezzo * 0.03 + porte * 5.0;
        }
};

int main() {
    Automobile auto1("AB123CD", 15000.0, 5);
    Automobile auto2("EF456GH", 22000.0, 3);

    cout << "Bollo " << auto1.targa << ": " << auto1.calcolaBollo() << " euro" << endl;
    cout << "Bollo " << auto2.targa << ": " << auto2.calcolaBollo() << " euro" << endl;
    return 0;
}

Per ora targa, prezzo e porte sono public: al livello successivo (incapsulamento) impareremo a proteggerli.

Esercizio 6 — Il puntatore this: rinominare una Persona ⭐ 📽️ Da proiettare

Consegna: crea una classe Persona con attributo nome e un metodo rinomina(string nome) il cui parametro si chiama esattamente come l'attributo. Usa this->nome per distinguere l'attributo dell'oggetto dal parametro locale.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class Persona {
    public:
        string nome;

        Persona(string nome) {
            this->nome = nome; // this->nome = l'attributo; nome (da solo) = il parametro
        }

        void rinomina(string nome) { // il parametro si chiama come l'attributo: serve "this" per distinguerli
            cout << "Rinomino " << this->nome << " in " << nome << endl;
            this->nome = nome;
        }
};

int main() {
    Persona p("Luca");
    p.rinomina("Marco");
    cout << "Nome attuale: " << p.nome << endl;
    return 0;
}

Dentro rinomina, scrivere semplicemente nome darebbe sempre il parametro (la regola è "vince il nome più vicino"): senza this-> non ci sarebbe alcun modo di leggere il vecchio valore dell'attributo prima di sovrascriverlo.

Esercizio 7 — Overload del costruttore: Prodotto ⭐ 📽️ Da proiettare

Consegna: crea una classe Prodotto (nome, prezzo, scorta) con tre costruttori in overload: uno completo, uno senza scorta (che parte da magazzino vuoto) e uno di default (prodotto segnaposto). A differenza dell'esempio visto in teoria, ogni costruttore deve inizializzare esplicitamente tutti gli attributi, anche quando il chiamante non fornisce un valore.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class Prodotto {
    public:
        string nome;
        double prezzo;
        int scorta;

        // costruttore completo
        Prodotto(string n, double p, int s) {
            nome = n;
            prezzo = p;
            scorta = s;
        }

        // costruttore senza scorta: parte da magazzino vuoto
        Prodotto(string n, double p) {
            nome = n;
            prezzo = p;
            scorta = 0; // inizializzato esplicitamente: mai lasciare un attributo "a caso"
        }

        // costruttore di default: prodotto segnaposto, tutti i campi hanno un valore sensato
        Prodotto() {
            nome = "sconosciuto";
            prezzo = 0.0;
            scorta = 0;
        }

        void stampa() {
            cout << nome << " - " << prezzo << " euro (scorta: " << scorta << ")" << endl;
        }
};

int main() {
    Prodotto p1("Quaderno", 1.50, 100); // usa il costruttore a 3 parametri
    Prodotto p2("Penna", 0.80);         // usa il costruttore a 2 parametri
    Prodotto p3;                        // usa il costruttore di default

    p1.stampa();
    p2.stampa();
    p3.stampa();
    return 0;
}

È lo stesso meccanismo di overload visto in teoria con la classe Persona a quattro costruttori, ma qui ogni versione assegna un valore a tutti e tre gli attributi: nessuno resta "spazzatura" non inizializzata, cosa che invece capitava a eta in persona3/persona4 nell'esempio della teoria.

2. Incapsulamento

Esercizio 8 — Getter e setter semplici: Rettangolo ⭐ 📽️ Da proiettare

Consegna: crea una classe Rettangolo con base e altezza private. Fornisci un getBase()/getAltezza() e un setBase()/setAltezza() che rifiutino valori non positivi (sostituendoli con 1). Il costruttore deve richiamare i setter, non assegnare direttamente.

Mostra soluzione in C++ (OOP) 
#include <iostream>
using namespace std;

class Rettangolo {
    private:
        double base;
        double altezza;
    public:
        Rettangolo(double b, double h) {
            setBase(b);      // il costruttore riusa i setter: la validazione vale sempre,
            setAltezza(h);   // sia alla creazione sia in qualsiasi modifica successiva
        }

        void setBase(double b) {
            if (b > 0) {
                base = b;
            } else {
                base = 1; // valore di sicurezza: un rettangolo non puo' avere base <= 0
            }
        }

        void setAltezza(double h) {
            if (h > 0) {
                altezza = h;
            } else {
                altezza = 1;
            }
        }

        double getBase() const { return base; }
        double getAltezza() const { return altezza; }

        double area() const {
            return base * altezza;
        }
};

int main() {
    Rettangolo r1(4.0, 3.0);
    cout << "Area r1: " << r1.area() << endl;

    Rettangolo r2(-5.0, 2.0); // base non valida: il setter la corregge automaticamente
    cout << "Base r2 (corretta): " << r2.getBase() << endl;
    cout << "Area r2: " << r2.area() << endl;
    return 0;
}

Far richiamare i setter anche dal costruttore (invece di scrivere base = b; due volte, con logiche diverse) garantisce che la regola di validazione sia scritta in un solo posto: se domani cambia, basta aggiornarla lì. Questo schema — attributi private + getter/setter che validano — è la base su cui si costruiscono gli esempi più ricchi che seguono.

Esercizio 9 — ContoBancario con controlli e trasferimento ⭐⭐ 📽️ Da proiettare

Consegna: nella classe ContoBancario, correggi deposita() perché rifiuti importi non positivi (come già fa preleva()), poi aggiungi un metodo pubblico trasferisci(ContoBancario& destinatario, double importo) che sposta denaro tra due conti usando solo i metodi pubblici già esistenti, senza mai accedere direttamente a saldo di un altro oggetto.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class ContoBancario {
    private:
        string intestatario;
        double saldo;
    public:
        ContoBancario(string nome, double saldoIniziale) : intestatario(nome), saldo(saldoIniziale) {}

        void deposita(double importo) {
            if (importo > 0) {
                saldo = saldo + importo;
            } else {
                cout << "Importo non valido per il deposito" << endl;
            }
        }

        bool preleva(double importo) {
            if (importo > 0 && importo <= saldo) {
                saldo = saldo - importo;
                return true;
            }
            cout << "Prelievo non valido" << endl;
            return false;
        }

        bool trasferisci(ContoBancario &destinatario, double importo) {
            if (preleva(importo)) {
                destinatario.deposita(importo);
                return true;
            }
            return false;
        }

        double getSaldo() const {
            return saldo;
        }
};

int main() {
    ContoBancario conto1("Luca", 1000.0);
    ContoBancario conto2("Anna", 200.0);

    conto1.deposita(-500.0);
    cout << "Saldo conto1 dopo deposito negativo: " << conto1.getSaldo() << endl;

    conto1.trasferisci(conto2, 300.0);
    cout << "Saldo conto1: " << conto1.getSaldo() << endl;
    cout << "Saldo conto2: " << conto2.getSaldo() << endl;

    conto1.trasferisci(conto2, 5000.0);
    conto1.trasferisci(conto2, -100.0);

    return 0;
}

trasferisci non ha bisogno di essere friend né di accedere a saldo di destinatario direttamente: saldo è private, ma stiamo chiamando metodi pubblici di un altro oggetto della stessa classe, ed è permesso.

Esercizio 10 — Cassaforte con PIN ⭐⭐ ✏️ Autonomo

Consegna: crea una classe Cassaforte con pin e contenuto privati. Il metodo pubblico apri(int pinInserito) deve restituire il contenuto solo se il PIN è corretto, altrimenti "ACCESSO NEGATO". La classe non deve esporre in nessun modo il valore del PIN (niente getPin()).

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class Cassaforte {
    private:
        int pin;
        string contenuto;
    public:
        Cassaforte(int pinIniziale, string contenutoIniziale) : pin(pinIniziale), contenuto(contenutoIniziale) {}

        string apri(int pinInserito) const {
            if (pinInserito == pin) {
                return contenuto;
            }
            return "ACCESSO NEGATO";
        }
};

int main() {
    Cassaforte cassaforte(1234, "documenti importanti");

    cout << cassaforte.apri(1234) << endl;
    cout << cassaforte.apri(9999) << endl;
    return 0;
}

Differenza importante: saldo è un dato privato che ha senso leggere dall'esterno (ha un getter), mentre pin è un dato privato che non deve mai averne uno — l'unico modo per "usarlo" è passarlo come tentativo a apri().

3. Ereditarietà

Esercizio 11 — Famiglia di Dipendenti ⭐⭐ 📽️ Da proiettare

Consegna: crea una classe base Dipendente (nome, stipendioBase) con un metodo stipendioNetto(), poi due classi figlie Manager (con un bonus) e Operaio (con ore di straordinario) che richiamano il costruttore della base nella lista di inizializzazione, senza duplicare nulla.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class Dipendente {
    protected:
        string nome;
        double stipendioBase;
    public:
        Dipendente(string n, double s) : nome(n), stipendioBase(s) {}

        double stipendioNetto() const {
            return stipendioBase;
        }

        string getNome() const {
            return nome;
        }
};

class Manager : public Dipendente {
    private:
        double bonus;
    public:
        Manager(string n, double s, double b) : Dipendente(n, s), bonus(b) {}
};

class Operaio : public Dipendente {
    private:
        int oreStraordinario;
    public:
        Operaio(string n, double s, int ore) : Dipendente(n, s), oreStraordinario(ore) {}
};

int main() {
    Manager m("Giulia", 3000.0, 500.0);
    Operaio o("Marco", 1800.0, 10);

    cout << m.getNome() << " - stipendio base: " << m.stipendioNetto() << endl;
    cout << o.getNome() << " - stipendio base: " << o.stipendioNetto() << endl;
    return 0;
}

Né Manager né Operaio ridefiniscono getNome() o stipendioNetto(): li ereditano così come sono da Dipendente. Nel costruttore, : Dipendente(n, s) è "la parte che eredita"; il resto del corpo è "la parte propria" della figlia.

Esercizio 12 — Libreria multimediale: Film e Podcast ⭐⭐ ✏️ Autonomo

Consegna: crea una classe base Media (titolo, durataMinuti) con un metodo stampaInfo(), poi due classi figlie Film (con un regista) e Podcast (con un numero di episodio) che richiamano il costruttore della base nella lista di inizializzazione, senza duplicare nulla.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class Media {
    protected:
        string titolo;
        int durataMinuti;
    public:
        Media(string t, int d) : titolo(t), durataMinuti(d) {}

        void stampaInfo() const {
            cout << titolo << " (" << durataMinuti << " min)" << endl;
        }
};

class Film : public Media {
    private:
        string regista;
    public:
        Film(string t, int d, string r) : Media(t, d), regista(r) {}
};

class Podcast : public Media {
    private:
        int numeroEpisodio;
    public:
        Podcast(string t, int d, int ep) : Media(t, d), numeroEpisodio(ep) {}
};

int main() {
    Film f("Inception", 148, "Christopher Nolan");
    Podcast p("Storie di Codice", 35, 12);

    f.stampaInfo();
    p.stampaInfo();
    return 0;
}

Stesso schema dell'esercizio 11: né Film né Podcast ridefiniscono stampaInfo(), lo ereditano così com'è da Media. Ognuna aggiunge solo il proprio attributo specifico e lo inizializza dopo aver richiamato il costruttore della base.

Esercizio 13 — Progetto Camion: capire virtual ⭐⭐⭐ 📽️ Da proiettare

Consegna: costruisci da zero una mini-famiglia Veicolo/Automobile/Camion in cui ogni figlia ridefinisce calcolaBollo() con una propria formula. Prova a chiamare il metodo tramite un riferimento Veicolo& rif = automobile;: senza virtual su calcolaBollo() in Veicolo, rif.calcolaBollo() restituisce il valore sbagliato (quello di Veicolo), anche se rif e l'oggetto originale sono la stessa cosa in memoria. Aggiungendo virtual il problema si risolve.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class Veicolo {
    protected:
        string targa;
        double prezzoBase;
    public:
        Veicolo(string t, double p) : targa(t), prezzoBase(p) {}

        virtual double calcolaBollo() const {
            return prezzoBase * 0.03;
        }
};

class Automobile : public Veicolo {
    private:
        int numeroPorte;
    public:
        Automobile(string t, double p, int porte) : Veicolo(t, p), numeroPorte(porte) {}

        double calcolaBollo() const override {
            return prezzoBase * 0.03 + numeroPorte * 5.0;
        }
};

class Camion : public Veicolo {
    private:
        double portataTon;
    public:
        Camion(string t, double p, double portata) : Veicolo(t, p), portataTon(portata) {}

        double calcolaBollo() const override {
            return prezzoBase * 0.02 + portataTon * 8.0;
        }
};

int main() {
    Automobile a("AB123CD", 15000.0, 5);
    Camion c("EF456GH", 40000.0, 12.0);

    cout << "Bollo (chiamata diretta): " << a.calcolaBollo() << endl;

    Veicolo &rif = a;
    cout << "Bollo (tramite Veicolo&, con virtual): " << rif.calcolaBollo() << endl;

    Veicolo &rifCamion = c;
    cout << "Bollo camion (tramite Veicolo&): " << rifCamion.calcolaBollo() << endl;

    return 0;
}

Senza virtual, il compilatore decide a compile-time quale calcolaBollo() chiamare guardando solo il tipo dichiarato di rif (Veicolo&), ignorando il tipo reale dell'oggetto puntato. Con virtual, la scelta avviene a runtime, in base al tipo reale dell'oggetto: è il ponte fra "tipo dichiarato" e "tipo reale" di cui parla la teoria del polimorfismo.

4. Polimorfismo (con puntatori grezzi)

Esercizio 14 — Zoo polimorfico ⭐⭐⭐ 📽️ Da proiettare

Consegna: crea una classe astratta Animale con virtual string verso() const = 0; e un distruttore virtuale, poi due figlie concrete (es. Cane, Gatto). Riempi un vector<Animale*> con new di entrambi i tipi mescolati, stampa il verso di ognuno senza alcun if sul tipo, poi distruggi ogni oggetto con delete.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class Animale {
    public:
        virtual string verso() const = 0;
        virtual ~Animale() {}
};

class Cane : public Animale {
    public:
        string verso() const override {
            return "Bau!";
        }
};

class Gatto : public Animale {
    public:
        string verso() const override {
            return "Miao!";
        }
};

int main() {
    vector<Animale*> zoo;
    zoo.push_back(new Cane());
    zoo.push_back(new Gatto());
    zoo.push_back(new Cane());

    for (size_t i = 0; i < zoo.size(); i++) {
        cout << zoo[i]->verso() << endl;
    }

    for (size_t i = 0; i < zoo.size(); i++) {
        delete zoo[i];
    }

    return 0;
}

Il puntatore in vector<Animale*> è "grezzo": nessuno lo distrugge al posto nostro, per questo serve il secondo ciclo con delete. Se ~Animale() non fosse virtual, delete zoo[i] chiamerebbe solo il distruttore di Animale, ignorando quello di Cane/Gatto (rischio concreto se le figlie avessero risorse proprie da liberare).

Esercizio 15 — Busta paga polimorfica ⭐⭐⭐ ✏️ Autonomo

Consegna: riprendi la famiglia Dipendente/Manager/Operaio dell'esercizio 11, rendi stipendioNetto() virtuale e falla ridefinire a ciascuna figlia con la propria formula (bonus per il manager, straordinari per l'operaio). Metti tre dipendenti in un vector<Dipendente*> e stampa lo stipendio di ognuno senza alcun if sul tipo.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class Dipendente {
    protected:
        string nome;
        double stipendioBase;
    public:
        Dipendente(string n, double s) : nome(n), stipendioBase(s) {}

        virtual double stipendioNetto() const {
            return stipendioBase;
        }

        string getNome() const {
            return nome;
        }

        virtual ~Dipendente() {}
};

class Manager : public Dipendente {
    private:
        double bonus;
    public:
        Manager(string n, double s, double b) : Dipendente(n, s), bonus(b) {}

        double stipendioNetto() const override {
            return stipendioBase + bonus;
        }
};

class Operaio : public Dipendente {
    private:
        int oreStraordinario;
    public:
        Operaio(string n, double s, int ore) : Dipendente(n, s), oreStraordinario(ore) {}

        double stipendioNetto() const override {
            return stipendioBase + oreStraordinario * 12.0;
        }
};

int main() {
    vector<Dipendente*> azienda;
    azienda.push_back(new Manager("Giulia", 3000.0, 500.0));
    azienda.push_back(new Operaio("Marco", 1800.0, 10));
    azienda.push_back(new Dipendente("Luca", 1500.0));

    for (size_t i = 0; i < azienda.size(); i++) {
        cout << azienda[i]->getNome() << ": " << azienda[i]->stipendioNetto() << " euro" << endl;
    }

    for (size_t i = 0; i < azienda.size(); i++) {
        delete azienda[i];
    }

    return 0;
}

Stesso schema dello Zoo polimorfico: un vector di puntatori alla classe base, un ciclo che chiama lo stesso metodo su tutti senza sapere il tipo reale, un secondo ciclo di delete. Qui però Dipendente non è astratta (può essere istanziata anche da sola, come "Luca"): la differenza con Animale è che non è obbligatorio ridefinire stipendioNetto(), perché non è virtuale puro.

Esercizio 16 — Calcolatrice polimorfica ⭐⭐⭐ ✏️ Autonomo

Consegna: crea una classe astratta Operazione con virtual double esegui(double a, double b) const = 0; e virtual string simbolo() const = 0;, poi quattro figlie concrete (Somma, Sottrazione, Moltiplicazione, Divisione). Riempi un vector<Operazione*> e applica ciascuna operazione agli stessi due numeri, stampando a simbolo b = risultato.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class Operazione {
    public:
        virtual double esegui(double a, double b) const = 0;
        virtual string simbolo() const = 0;
        virtual ~Operazione() {}
};

class Somma : public Operazione {
    public:

        string simbolo() const override { return "+"; }
};

    public:
        double esegui(double a, double b) const override { return a - b; }
        string simbolo() const override { return "-"; }
};

    public:
        double esegui(double a, double b) const override { return a * b; }
        string simbolo() const override { return "*"; }
};

class Divisione : public Operazione {
    public:
        double esegui(double a, double b) const override { return a / b; }
        string simbolo() const override { return "/"; }

int main() {
    double a = 10, b = 3;

    vector<Operazione*> operazioni;
    operazioni.push_back(new Somma());
    operazioni.push_back(new Sottrazione());
    operazioni.push_back(new Moltiplicazione());
    operazioni.push_back(new Divisione());

    for (size_t i = 0; i < operazioni.size(); i++) {
        delete operazioni[i];
    }

    return 0;

A differenza dello Zoo e della Busta paga, qui il metodo polimorfico (esegui) prende parametri: il meccanismo non cambia, ogni oggetto nel vector risponde alla stessa chiamata esegui(a, b) con la propria formula, decisa a runtime in base al tipo reale.

Esercizio 17 — Forme geometriche astratte ⭐⭐ 📽️ Da proiettare

Consegna: crea una classe astratta Forma con due metodi virtuali puri, area() e perimetro(), e un distruttore virtuale. Implementale in Rettangolo e Cerchio, poi usale tramite un vector<Forma*>, distruggendo ogni oggetto con delete a fine programma.

#include <iostream>
#include <vector>
using namespace std;

class Forma {
    public:
        virtual double area() const = 0;
        virtual double perimetro() const = 0;
        virtual ~Forma() {}
};

class Rettangolo : public Forma {
    private:

    public:

        }

        double perimetro() const override {
            return 2 * (base + altezza);
        }
};

    private:
        double raggio;
    public:
        Cerchio(double r) : raggio(r) {}

        double area() const override {
            return 3.14159 * raggio * raggio;
        }

        double perimetro() const override {
            return 2 * 3.14159 * raggio;
        }
};

int main() {
    // Forma f; // ERRORE: non si puo' istanziare una classe astratta

    vector<Forma*> forme;

    forme.push_back(new Cerchio(5.0));

    for (size_t i = 0; i < forme.size(); i++) {

Esercizio 18 — Elettrodomestici: un metodo puro e uno con comportamento di default ⭐⭐ ✏️ Autonomo

Consegna: crea una classe astratta Elettrodomestico (attributo modello) con un metodo virtuale puro consumoWatt() e un metodo virtuale non puro stampaScheda(), che stampa modello e consumo richiamando consumoWatt() al proprio interno.     public:

Esercizio 19 — Virtuale puro vs virtuale normale ⭐⭐⭐ 📽️ Da proiettare

Consegna: in una famiglia Veicolo/Automobile/Motocicletta con calcolaBollo() virtuale puro in Veicolo, verifica cosa succede se una figlia non lo ridefinisce (resta astratta anche lei, errore di compilazione sulla figlia) e cosa succede se dimentichi solo la parola chiave override pur mantenendo la firma corretta (compila comunque, ma override resta la scelta giusta perché fa scoprire al compilatore eventuali errori di firma).

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
using namespace std;

class Veicolo {
    protected:
        string targa;
        double prezzoBase;
    public:
        Veicolo(string t, double p) : targa(t), prezzoBase(p) {}

        virtual double calcolaBollo() const = 0; // virtuale PURO: obbliga le figlie a implementarlo
};

class Automobile : public Veicolo {
    private:
        int numeroPorte;
    public:
        Automobile(string t, double p, int porte) : Veicolo(t, p), numeroPorte(porte) {}

        // Anche senza scrivere "override", questo metodo ridefinisce comunque
        // calcolaBollo() perche' nome e firma coincidono: compila lo stesso.
        double calcolaBollo() const {
            return prezzoBase * 0.03 + numeroPorte * 5.0;
        }
};

class Motocicletta : public Veicolo {
    private:
        int cilindrata;
    public:
        Motocicletta(string t, double p, int cc) : Veicolo(t, p), cilindrata(cc) {}

        double calcolaBollo() const override {
            return prezzoBase * 0.01 + cilindrata * 0.02;
        }
};

/* Se si commenta l'override di calcolaBollo() in Motocicletta, la classe
   resta con un metodo virtuale puro non implementato: diventa anch'essa
   astratta, e "Motocicletta m(...)" nel main da' errore di compilazione.
   L'errore riguarda Motocicletta, non Veicolo: e' lei che rompe il contratto. */

int main() {
    Automobile a("AB123CD", 15000.0, 5);
    Motocicletta m("XY789ZZ", 8000.0, 600);

    cout << "Bollo auto: " << a.calcolaBollo() << endl;
    cout << "Bollo moto: " << m.calcolaBollo() << endl;
    return 0;
}

override non è obbligatorio, ma conviene scriverlo sempre: se per errore la firma della figlia non corrisponde esattamente a quella della base (es. un parametro const in meno), senza override il compilatore crea silenziosamente un metodo nuovo invece di segnalare l'errore; con override lo blocca subito.

            cout << attaccante.getNome() << " infligge " << danno << " danni a "
                 << bersaglio.getNome() << "." << endl;
            bersaglio.stampaStato();
        }

        turnoDiP1 = !turnoDiP1;
    }

    if (p1.eVivo()) {
        cout << endl << p1.getNome() << " vince il duello!" << endl;
    } else {
        cout << endl << p2.getNome() << " vince il duello!" << endl;
    }
}

int main() {
    srand(time(0));

    string nome1, nome2;
    cout << "Nome del giocatore 1: ";
    cin >> nome1;
    cout << "Nome del giocatore 2: ";
    cin >> nome2;

    Personaggio *p1 = creaPersonaggio(nome1);
    Personaggio *p2 = creaPersonaggio(nome2);

    combatti(*p1, *p2);

    delete p1;
    delete p2;

    return 0;
}

combatti() continua a prendere Personaggio&, quindi la chiamiamo come combatti(*p1, *p2) dereferenziando i puntatori. Chi crea gli oggetti con new (qui il main) è responsabile di distruggerli con delete, qualunque sia il vincitore: per questo delete p1; e delete p2; vengono eseguiti sempre, a fine partita.

Esercizio 25 (stretch, facoltativo) — Torneo a squadre ⭐⭐⭐⭐ ✏️ Autonomo

Consegna: crea una classe Squadra che possiede (composizione) un vector<Personaggio*> creato con new, e che nel proprio distruttore ~Squadra() distrugge tutti i suoi membri con delete. Realizza un piccolo torneo a squadre in cui, a turno, ogni squadra attacca con il primo membro ancora vivo.

Mostra soluzione in C++ (OOP) 
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class Personaggio {
    protected:
        string nome;
        int puntiVita;
        int puntiVitaMax;
    public:
        Personaggio(string n, int vita) : nome(n), puntiVita(vita), puntiVitaMax(vita) {}
        bool eVivo() const { return puntiVita > 0; }
        void subisciDanno(int danno) {
            puntiVita -= danno;
            if (puntiVita < 0) puntiVita = 0;
        }
        string getNome() const { return nome; }
        virtual int attacca() const = 0;
        virtual void stampaStato() const {
            cout << nome << ": " << puntiVita << "/" << puntiVitaMax << " PV" << endl;
        }
        virtual ~Personaggio() {}
};

class Guerriero : public Personaggio {
    public:
        Guerriero(string n) : Personaggio(n, 120) {}
        int attacca() const override { return 15; }
};

class Mago : public Personaggio {
    public:
        Mago(string n) : Personaggio(n, 70) {}
        int attacca() const override { return 25; }
};

class Squadra {
    private:
        string nomeSquadra;
        vector<Personaggio*> membri;
    public:
        Squadra(string n) : nomeSquadra(n) {}

        // Distruttore: la squadra "possiede" i suoi personaggi
        // (li ha creati lei con new), quindi tocca a lei distruggerli.
        ~Squadra() {
            for (size_t i = 0; i < membri.size(); i++) {
                delete membri[i];
            }
        }

        void aggiungi(Personaggio *p) {
            membri.push_back(p);
        }

        bool haSuperstiti() const {
            for (size_t i = 0; i < membri.size(); i++) {
                if (membri[i]->eVivo()) return true;
            }
            return false;
        }

        Personaggio* primoVivo() {
            for (size_t i = 0; i < membri.size(); i++) {
                if (membri[i]->eVivo()) return membri[i];
            }
            return nullptr;
        }

        string getNome() const { return nomeSquadra; }
};

int main() {
    Squadra rossi("Squadra Rossa");
    rossi.aggiungi(new Guerriero("Thorin"));
    rossi.aggiungi(new Mago("Elara"));

    Squadra blu("Squadra Blu");
    blu.aggiungi(new Guerriero("Conan"));
    blu.aggiungi(new Mago("Merlino"));

    bool turnoRossi = true;
    while (rossi.haSuperstiti() && blu.haSuperstiti()) {
        Squadra &attaccanti = turnoRossi ? rossi : blu;
        Squadra &difensori = turnoRossi ? blu : rossi;

        Personaggio *attaccante = attaccanti.primoVivo();
        Personaggio *bersaglio = difensori.primoVivo();

        int danno = attaccante->attacca();
        bersaglio->subisciDanno(danno);
        cout << attaccante->getNome() << " (" << attaccanti.getNome() << ") colpisce "
             << bersaglio->getNome() << " (" << difensori.getNome() << ") per " << danno << " danni." << endl;

        turnoRossi = !turnoRossi;
    }

    if (rossi.haSuperstiti()) {
        cout << rossi.getNome() << " vince il torneo!" << endl;
    } else {
        cout << blu.getNome() << " vince il torneo!" << endl;
    }

    // I distruttori di rossi e blu vengono chiamati automaticamente qui,
    // ed eliminano a cascata tutti i Personaggio* creati con new.
    return 0;
}

Notate quanto lavoro ripetitivo serve per gestire a mano ogni singolo delete (qui e in tutti gli esercizi precedenti con puntatori grezzi): è esattamente il tipo di responsabilità che uno unique_ptr toglierebbe di mezzo automaticamente, occupandosi da solo della distruzione quando l'oggetto non serve più.
